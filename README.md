# z-compliance-review-service

## Overview

z-compliance-review-service is a Spring Boot–based microservice that performs compliance review in a GenAI multi-agent system.

It is designed as **Agent C** in the architecture, responsible for:

- Making **deterministic compliance decisions** using rule-based logic
- Generating **LLM-assisted explanations** for better user experience
- Retrieving compliance context from **pgvector (PostgreSQL)**
- Processing requests asynchronously via **Kafka**

---

## Key Responsibilities

- Evaluate customer eligibility based on policy rules
- Enforce KYC, risk, and income constraints
- Ensure decisions are **auditable and reproducible**
- Generate human-readable explanations using LLM
- Maintain compliance history

---

## Architecture Role

```text
z-wealth-knowledge-rag (Agent A)
        |

        v
```

## Core Design Principle

- Rules decide, LLM explains.
- Decision is made by rule-based logic (deterministic)
- Explanation is generated by LLM (optional, non-critical)

## Rule Engine

Examples:

Reject if KYC is not VERIFIED
Reject if income below threshold
Reject if risk level not suitable
Approve otherwise

Example logic:

```java
if (!"VERIFIED".equals(customer.getKycStatus())) return REJECTED;
if ("HIGH".equals(customer.getRiskLevel())) return REJECTED;
if (customer.getAnnualIncome() < 30000) return REJECTED;
return APPROVED;
```

---

## LLM Integration

OpenAI → Ollama → Rule fallback

Uses LangChain4j
Calls OpenAI (or fallback to local Ollama)
Generates explanation only (not decision)

Fallback strategy:

1. Try OpenAI
2. Fallback to Ollama
3. If both fail → return rule-based explanation

---

## Vector Search

pgvector stores compliance documents and retrieves context for explanation，improves grounding and reduces hallucination。
